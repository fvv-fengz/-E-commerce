# 抖店生态试运行 — 任务说明（按模块）

本文说明：**全量试运行在业务上要完成什么**。依据模板 **`doc/scrape-template-jinritemai-v1.json`**，由 **`scripts/run_template_trial.py`** 驱动；细节参数、选择器以模板与脚本为准。

**命令行**（如多店、只跑某几页、断点续跑）只影响「跑哪些店 / 哪些页」，**不改变**下面单店内模块的先后顺序。

---

## 总览：多店时的一条流水线

对配置里的**每家店**，顺序固定为：

1. **进店**：回到抖店商家首页，把当前会话**切换成这家店**（按账户名）。
2. **按页跑任务**：依次完成下面 **5 个页面模块**（与模板 `globalAccountLoop.pageIds` 一致；其中**资金账单生成**与**历史报表下载**在业务上算**同一环节**，技术上拆成两个 page id，且**紧相邻执行**）。

| 顺序 | 失败汇总代号 | 页面 id / 概念 | 这件任务在干什么 |
|------|----------------|----------------|------------------|
| 1 | **B** | `fxg_aftersale_fund_detail_bill` → 紧接 `fxg_bill_history_report` | **同一资金环节**：侧栏进账单管理，选日并**生成报表**；随即在历史报表列表对**首条**点**下载**（若上一步已 SPA 到历史页，`goto` 可能 `skip_same_url`） |
| 2 | **A** | `fxg_mshop_home` | 进入罗盘店铺页，顶栏日期后再读三项经营指标 |
| 3 | **C** | `fxg_aftersale_order_list_export` | 筛售后单并**导出** |
| 4 | **D** | `qianchuan_home_cost_roi` | 千川成本卡选昨日并读三项指标 |

进店切换插在每家店、上表**第 1 步**之前，由 `globalAccountLoop` 驱动，**不单独占** `pageIds` 里的一格。

**千川（D）与账户配置**：若模板里启用了「按千川 ID」且某店**没配千川 ID**，则该店**跳过 D**，指标记为 `None`；若无人配千川 ID，则千川仍可按**店铺名**切户（与旧行为一致）。

---

## 进店与切店（抖店）

**目的：** 保证后续所有页面都在**正确的店铺**后台里操作。

| 步骤 | 在做什么事 |
|------|------------|
| 1 | 进入抖店**商家首页**（`preSwitchUrl`，可切店状态） |
| 2 | 在顶栏账号区打开**切换组织/店铺**，在列表里选中**当前轮次对应的店名**（须与配置中的店铺名一致） |

---

## B · 资金账单全流程（同一环节 · 两页紧接）

以下两段在 **`pageIds` 中相邻**，与 `run_template_trial.py` 里失败汇总代号 **B** 对应（两页同属 **B**）。

### B1 · 账单管理 / 生成（`fxg_aftersale_fund_detail_bill`）

**目的：** 在**账单管理**页把查询日期设好并**提交生成报表**；**本页不下载文件**。

| 步骤 | 在做什么事 |
|------|------------|
| B1-0 | 从抖店首页经左侧栏 **常用（nth-child(2)）内「账单管理」优先**，失败再 **资金 → 账单管理** 进入 `fund-detail-bill`；侧栏三步点击在模板里为 `clickWaitForState: attached`（只等节点挂树，**不等**主内容区完全可见）+ `skipScrollIntoView`（与 `preSwitchUrl` 同为首页时可能不重复 `goto`） |
| B1-1 | 把动账**日期范围**设为**昨天**（自然日） |
| B1-2 | 点 **「生成报表」**；浮层里 **「确定」** |

### B2 · 历史报表 / 下载（`fxg_bill_history_report`）

**目的：** 只下载**列表最上面一条**对应文件；**不要**在首条还是「生成中」时去点第二条的「下载」。

| 步骤 | 在做什么事 |
|------|------------|
| B2-1 | 进入历史报表列表（常与 B1 末尾为同一浏览器路径衔接）；若首条仍是「生成中」，在超时内**轮询**，必要时**刷新**，直到首条出现「下载」再点击 |
| B2-2 | 若仍失败：按模板 **continueOnFail** 等策略处理，不拖死后续页面 |

## A · 罗盘店铺页（`fxg_mshop_home`，URL：`compass.jinritemai.com/shop`）

**目的：** 在 [抖音电商罗盘](https://compass.jinritemai.com/shop) 店铺视角下，先按顶栏 **日期** 选好统计区间，再采集与首页一致口径的三块经营数据（支付金额、成交订单数、客单价），供汇总表与 `postprocess_home_blob_metrics` 解析。

**切店**仍在**进店**流程的 `preSwitchUrl`（抖店商家首页）完成；本页是罗盘子域，脚本在当前标签页 **`goto` 打开上述 URL**（不经过抖店 PC 顶栏再点进罗盘）。

| 步骤 | 在做什么事 |
|------|------------|
| A0 | 若地址已是罗盘店铺页，可 `skip_same_url` 避免重复整页刷新 |
| A1 | 等待首屏与 `#homepage-top-datepicker` 等区域渲染（模板 `postGotoWaitMs` / `preFieldExtractWaitMs`） |
| A2 | **点顶栏日期筛选**：主选为 `#homepage-top-datepicker … label.ecom-radio-button-wrapper-checked`；若需固定选「昨日 / 近1日」等，模板里已备 `alternateClickSelector` 文案兜底（`-checked` 会随当前选中项变化） |
| A3 | **只读页面文字（三合一）**：直接读取经营概况容器 `#root > div.homepageWrapper-zxLmZT > div > dynamic-module-wrapper:nth-child(1) > div > div > div.coreContent-J7jCZG > div.businessDataWrap-LUgNmI > div:nth-child(1) > div > div.ecom-spin-nested-loading > div > div:nth-child(1)` 的全部可见文本，后处理再解析用户支付金额/客单价/成交订单数；不再逐指标定位三次。 |

本模块**有**日期筛选交互，再读数。

## C · 售后单列表 · 筛选与导出（`fxg_aftersale_order_list_export`）

**目的：** 按业务约定筛一批售后单，并**导出**为文件（如 Excel），供离线核对或归档。

| 步骤 | 在做什么事 |
|------|------------|
| C0 | 直达售后单列表页（不依赖侧栏菜单） |
| C1 | 若筛选区折叠，先**展开**筛选区 |
| C2 | 筛售后状态：**退款成功** |
| C3 | 筛发货物流：**买家已签收** |
| C4 | 筛时间：**昨日**（与页面文案「昨天/昨日」可能对齐） |
| C5 | 点 **查询**，应用筛选 |
| C6 | 点 **导出**，等待文件下载 |

本模块**不采集字段**，只导出文件。

## D · 巨量千川 · 首页成本卡（`qianchuan_home_cost_roi`）

**目的：** 在千川首页「成本」相关卡片上，把日期对齐到**昨天**，并读取**三个**投放成本/成交相关数字，写入采集结果。

**常见配置含义（与模板一致即可）：**

- **URL 带千川账户 ID**：减少落地后再找账户的步骤。
- **跳过落地后切户**：若已用 URL 直达账户，则不再在页内重复选店。
- **关蒙层**：选日期、读数前尽量关掉推广弹窗等遮挡。
- **整页失败时的占位**：可按模板写成 `none` 等，避免卡死多店任务。

| 步骤 | 在做什么事 |
|------|------------|
| D0 | 打开千川首页（必要时 URL 已带当前店对应的投放账户参数） |
| D1 | （仅当需要页内切户时）在账户列表或搜索里选中**当前店对应的投放账户** |
| D1a | 关闭挡在日期、指标上的弹窗或蒙层 |
| D2 | 在成本卡上把日期设为 **昨天**（通常通过日期入口 + 快捷项） |
| D3 | **只读三个指标**的数值（如消耗、ROI 相关、净成交订单数等，以模板字段为准） |

若策略为「本店未配千川 ID 则跳过」：**不打开千川**，三个指标直接记 **`None`**（与「进页失败写的占位符」含义不同，以日志/表头为准）。

**异常与超时（示例，便于对照主模板 `qianchuan_home_cost_roi` 与 `run_template_trial.py`）：**

| 情形 | 典型怎么处理 | 数量级（默认或主模板） |
|------|----------------|------------------------|
| 打开千川页后等首屏 | `postGotoWaitMs` | 主模板 **1250 ms** |
| 若启用「页内切户」：等账户列表 | `shopListWaitTimeoutMs` 等 | 模板里常见 **17500 ms**；点中账户后还有 `afterClickWaitMs`（如 **2500 ms**） |
| 交互步里等控件可见再点 | `waitVisibleTimeoutMs`（若有） | 脚本对交互步常有一个**上限**（可被命令行 `--interaction-timeout-ms` 整体抬高或截断） |
| 抽字段：等选择器出现并读文本 | `field_locator_timeout_ms`（命令行） | 默认 **30000 ms** 内等不到则该字段失败；**原理见下节「附：抽字段原理」** |
| 千川**整页**跑完仍缺数 / 失败 | `qianchuanRetryExtra` | 主模板为 **0**（不重试）；可改为 **1～10**，脚本在两次尝试之间固定等 **`_QIANCHUAN_RETRY_WAIT_MS` = 2000 ms**，并截断本轮已写入的行再重跑整页 |
| 整页最终仍失败且开了软失败 | `softFailPage` + `softFailPlaceholder` | 主模板为 **`none`**（小写），三个指标可统一记占位，**不拖死**后面店铺 |
| 关蒙层仍挡不住 | 人工关掉弹窗后重跑，或加大 `postGotoWaitMs` / 交互等待 | 无固定秒数，属运维侧 |

**一句话：** 「等多久算超时」分散在 **进页等待、交互可见、字段定位、整页重试间隔** 几处；具体毫秒以模板字段和脚本默认值为准，全局可加 **`--interaction-timeout-ms`**、**`--field-locator-timeout-ms`** 等放宽。

## 附：抽字段原理（`fields` · `extract.type`: text）

脚本里「抽字段」**不是**截图 OCR，而是 **Playwright 用 CSS/XPath 在 DOM 里定位节点，再读 `inner_text()`**（可见范围内的文字）。

1. **模板来源**  
   每条指标对应 `pages[].fields[]` 里一项：`selector` 为主；可配 **`alternateFieldSelector`**（字符串或数组）作为**备选链**。当前试运行**只实现** `extract.type` 为 **text**（缺省也是 text）。

2. **候选顺序**  
   若有 **`--selector-hints-file`**（默认 `log/field_selector_hints.json`），会把**该店、该页、该字段上次跑通**的选择器插到**最前面**，再与主选 + 备选合并去重，依次尝试。

3. **单字段单次尝试**（对每个候选选择器）  
   - `page.locator(选择器).first` 定位**第一个**匹配节点。  
   - 先 **`wait_for(state="attached")`**，在 **`field_locator_timeout_ms`**（命令行，默认 **30000 ms**）内等节点挂到 DOM；再 **`inner_text()`** 取文案。  
   - 若附着后文本仍空，会再试 **`wait_for(visible)`** 后读一次（仍受同一套超时预算约束；脚本内部读文本还有一次约「超时一半、且夹在 3～25 秒」的 `inner_text` 子超时）。

4. **超时与截断**  
   - 单字段总等待主要来自 **`--field-locator-timeout-ms`**，并可能与 **`--interaction-timeout-ms`** 一起参与「可见等待上限」的封顶（见脚本 `_cap_visible_ms`）。  
   - 若页面配置了 **字段抽取总预算** `field_extract_budget_ms`，则整页多个字段**共享**剩余时间，避免单页拖太久。

5. **抽之前**  
   若模板 **`dismissBlockingOverlaysBeforeFields`** 为 true（千川页默认），每个字段前会尝试关掉挡在指标上的蒙层/营销弹窗，再定位。

6. **千川特例**  
   若第一个成本指标读出来是 **`--`** 这类「无数据」占位，脚本可能**不再抽后两个字段**，三个指标统一按「无数据」规则填（见脚本 `_qianchuan_first_metric_is_empty_dash` 等）。
